# Decision log

Every decision that shapes Fantasy Code RPG, newest first. When a decision changes, add a new row that says what it replaces; never delete old rows. The full reasoning lives in [DESIGN_PLAN.md](DESIGN_PLAN.md).

| Date | Decision | Why | Replaces |
|---|---|---|---|
| 2026-10-23 | **The browser game is plain HTML, CSS and JavaScript in `src/web/`, one file per concern** (words, plumbing, town, scenes, battle). No framework and no build step. Windows and menus are real HTML text; pixel art is drawn on canvases. | Anyone can open a file and improve one scene; text stays translatable and readable by screen readers. | One page file |
| 2026-10-23 | **Guild Town is painted from the game's state**, not a fixed picture: buildings glow when something waits there, the Quest Board shows one notice per open quest, the Battle Gate swirls and a pillar of light rises while a battle runs, and the rain speeds up when heroes are busy. | Every pixel does a job. | Static town mockup |
| 2026-10-23 | **The browser uses the engine's own functions** for every command (request, answer, plan, approve, battle, keep, undo, recruit, settings). Changes run one at a time, and while a battle runs other changes wait until it ends. | One set of rules whether you play in the terminal or the browser; no lost updates. | — |
| 2026-10-23 | **Language and play style are game settings; window style and reduced motion are per-browser preferences.** Quest text and hero names stay as written; rank titles and quest types are translated on screen. | Heroes keep working in whatever language you write to them. | — |
| 2026-10-23 | **Novices wear a plain grey-green tunic.** | The old brown tunic read as bare skin on darker skin tones. | Brown tunic |
| 2026-10-23 | **The browser game is a tiny local server** (`savepoint play`): Node's own `http`, Server-Sent Events for the live stream and plain POSTs for your commands, bound to 127.0.0.1 with a one-time key in the link. Hero settings and keys are never sent to the page. | Zero dependencies; nothing goes online; any other page on your computer can't drive it. | WebSocket (UX plan §10) |
| 2026-10-23 | **One event file is the game's nervous system.** Battles, reviews and every tool call (via the Gatekeeper hook) append to `chronicle/events.jsonl`; the browser follows it. | A battle started from any terminal, or by any CLI, shows up live on screen. | — |
| 2026-10-23 | **The browser draws heroes and monsters with the same generators as the design canvas** (`assets/generators/*.cjs`, plain ES5). | One art pipeline; what you approve in the Style Bible is what you see in play. | Separate sprite sheets |
| 2026-10-23 | **One rulebook for three CLIs.** `savepoint gate --cli claude|codex|gemini` translates each CLI's tool names (Codex `apply_patch`, Gemini `write_file`, `run_shell_command`…) into the same rules and answers in each CLI's own format. Claude Code gets a settings file; Codex gets `-c hooks.*` overrides; Gemini CLI gets an extra settings layer. Sandbox flags stay the first wall. | Trust must mean the same thing whichever company's CLI a hero runs on. | Claude Code-only Gatekeeper |
| 2026-10-23 | **No proof, no victory, inside the CLI.** When a hero tries to stop (Claude Code and Codex `Stop`, Gemini `AfterAgent`), the quest's command checks run; if any fail, the hero is sent back with the failure output, at most 3 times per battle. | Heroes finish the job instead of claiming it; the cap stops a stuck hero looping. | — |
| 2026-10-23 | **GitHub Issues import** through the player's own `gh` command (`savepoint import github`). Labels set the quest type only when they agree; otherwise the Clerk reads the issue. Issue text is treated as material, never as instructions. | Most projects already track work there; no tokens to manage. | — |
| 2026-10-23 | **Desk jobs are read-only.** The Clerk, Scout and Planner run with Novice permissions whatever their rank, so the Request and War Room stages are safe to run automatically. | They plan; they never change anything. | — |
| 2026-10-23 | **AI-proposed checks must pass the Gatekeeper** as if a Tier 2 hero ran them (no network, no pushing, nothing forbidden); otherwise the condition goes to judges. | Story mode approves quests automatically, so a proposed command must already be safe. | — |
| 2026-10-23 | **Unclear requests and over-sized quests loop back.** The Clerk or Scout can raise up to 3 questions (a Sphinx blocks the road until you answer) or suggest a split (a Chimera); nobody fights until it's resolved. | Most failed tasks were never defined. | — |
| 2026-10-23 | **In Story mode the War Room runs on its own before a battle; in Adventurer and Tactician you run `plan` and `approve`.** A new plan always needs your nod outside Story mode. | Matches the play styles: results first for newcomers, control for those who want it. | — |
| 2026-10-23 | **Judging:** run the checks first; then up to three judges, one per AI company before doubling up, never anyone who fought. Authors are hidden, each judge sees the conditions in a different order, and each condition is its own Council decision that needs a unanimous vote; a split goes to you. | Independent mistakes and no self-preference; a split is exactly when your eye is worth it. | A single judge per battle |
| 2026-10-23 | **Conditions only you can judge** don't count against the party; the battle can be a victory while they wait at the Treasure Vault, and Keep is your confirmation. Undo rejects them and counts as a loss. | Taste and business calls belong to you, without penalising the heroes for waiting. | — |
| 2026-10-23 | **Battles run in a private copy of the project** (a git worktree on branch `savepoint/<battle>`), kept outside the project folder (`~/.cache/savepoint/instances`, override with `SAVEPOINT_INSTANCES`). A save point is committed after each hero's turn. | Your folder is never touched until you choose Keep; any step can be undone; parallel battles can't collide. Outside the project so editors and tests never see it, and outside `.savepoint/`, which the Gatekeeper forbids. | Running in your folder with a single save point |
| 2026-10-23 | **Treasure Vault: Keep merges, Undo discards.** An undone victory counts as a loss for the whole party and marks the Council's choice wrong. Critical failures are discarded automatically. | Your verdict outranks the judge's, and trust has to reflect it. | — |
| 2026-10-23 | **The Council decides with five seats:** Law (rules) → Ledger (win records) → Seer (cheap fast model) → Trial (run it, then vote across companies) → You. A seat answers only above the bar for that kind of decision (0.95 for hard-to-undo, 0.85 otherwise). Every decision is written to `chronicle/decisions.jsonl`; the Debrief marks it right or wrong in `outcomes.jsonl`. | Most decisions become free and instant; expensive judgment and your attention go where they matter; accuracy is measured, not assumed. | Hard-coded routing |
| 2026-10-23 | **The Ledger uses Thompson sampling over win records per quest type × hero.** It answers only when one hero is likely the best (≥ 85%). | Learns from your guild's real results; with little data it stays humble and passes the question up. | — |
| 2026-10-23 | **Vote, don't debate. Run code before judging code. Mix companies for judging, not for doing.** | Research: majority voting delivers most of debate's gains; execution beats LLM judging for code; same-model sampling beats mixed generation, but judges favour their own company's writing. | — |
| 2026-10-23 | **Allies policy:** outside tools (Jev, Arch-Router, LiteLLM, small judge models…) are optional adapters, must earn their seat on our own win records, and fail by passing the question up. Jev is an example, not a requirement. | Keeps the engine at zero runtime dependencies and protects outcomes from vendor churn. | — |
| 2026-10-23 | **Subscriptions:** we only drive the official, unmodified CLI the player logged into themselves, never touch its login tokens, and use API keys for anything else. | Anthropic's terms forbid third-party tools from using Pro/Max logins on a user's behalf. | — |
| 2026-10-23 | **Licences:** borrow ideas, not code, from AGPL projects (Claude Squad, Basic Memory) and Task Master (Commons Clause). Arch-Router and Patronus Glider stay out until their licences are checked. | MIT project; no copyleft or non-commercial code. | — |
| 2026-10-23 | **New players start in Story mode**; after three quests (sooner if they open plans or swap heroes) the game offers Adventurer. It never switches without asking. | Results before machinery; power users reveal themselves. | Open question |
| 2026-10-23 | **Task trackers:** GitHub Issues built in; everything else through MCP connectors the player already has, or pasted text. | One integration to maintain. | Open question |
| 2026-10-23 | **One budget per quest** (default by quest type); Pincer and Siege must fit inside it. Pincer is only recommended for high stakes: a returning Hydra, a risky quest, or a failed first try. | One money rule. | Open question |
| 2026-10-23 | **Explore quests ship at launch; Write soon after.** | Explore is read-only, safe and the most useful quest for non-technical players. | Open question |
| 2026-10-23 | **Party size 4** (Lead, Support, Scout, Judge). Siege runs several parties; advisors take no slot. | Matches the roles and the classic 16-bit party. | Open question |
| 2026-10-23 | **Six quest types** (Build, Fix, Improve, Explore, Maintain, Write) set the default party, formation, budget and proof. The Law classifies from keywords only when exactly one type matches. | Players never configure quests by hand. | — |
| 2026-10-23 | **Seven-stage quest loop**, one scene per stage: Request (Guild Counter) → Scout → Plan → Form party (War Room) → Battle → Review (Treasure Vault) → Debrief (Library). You decide at Request, Plan and Review; in Story mode only at Review. | Each stage exists because skipping it is how AI work usually goes wrong. | Quest Board → Form Party → Battle → Loot |
| 2026-10-23 | **Engine and CLI keep the name `savepoint`; the game is Fantasy Code RPG.** | A save point is a game concept that fits the engine; renaming the CLI now would churn every doc and script. | — |
