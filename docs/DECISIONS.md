# Decision log

Every decision that shapes Fantasy Code RPG, newest first. When a decision changes, add a new row that says what it replaces; never delete old rows. The full reasoning lives in [DESIGN_PLAN.md](DESIGN_PLAN.md).

| 2026-10-23 | **Siege: one quest, fought in parts at the same time.** A part is a name plus the victory conditions it covers. The Scout suggests parts when the work splits cleanly (or you set them with `savepoint split`); up to four parts run at once, each in its own copy, and are joined in the order listed. A part whose changes clash with earlier ones is set aside for the next battle. | Parallel work without a merge-conflict lottery: the clash rule is simple and nothing is half-merged. | "Split" meaning "request each one as its own quest" |
| 2026-10-23 | **In a Siege, each hero answers for their own part.** Trust counts only their part's conditions; a part set aside after a clash isn't counted either way; the stop gate only holds a hero to their part's checks. | Fair credit when several heroes share one quest. | — |
| 2026-10-23 | **A quest split into parts is fought as a Siege by default**, and the War Room plans it as one quest instead of stopping. `--formation relay` fights it as one. | The Scout's split is a plan, not a dead end. | War Room stopping on "split" |
| 2026-10-23 | **Heroes may ask for one rank above their own, nothing higher.** Claude Code is given the next rank's tools, and the Gatekeeper pauses before any of them runs. Two or more ranks up is refused outright, with no question and no penalty. | The first real Claude Code run showed that the CLI's own plan mode stopped a novice before it could even ask, so Wait mode never fired. One rank up keeps the questions few and the steps of trust small. | Wait mode: "a hero that tries something above its rank is paused and asks you" |
| 2026-10-23 | **Desk jobs never ask.** The Clerk, Scout, Planner, Seer, scribe and judges stay strictly read-only, and the stop gate leaves them alone. | You should only ever be asked about work on the quest itself. | — |

| 2026-10-23 | **Saying no is never held against the hero.** A lost battle in which you refused a request (or let it time out) is a retreat, not a defeat. | The prompt promises that asking is safe; the trust record now keeps that promise. | — |
| 2026-10-23 | **No judge free means you decide.** Conditions that need a judge when none is available go to you at the Treasure Vault, like a split vote, instead of counting as unmet. | 2026-10-23 | **Lessons are about the project only:** the scribe is told the private copy is normal and why the battle ended, absolute paths become `<path>`, and lessons about the guild's own machinery are dropped. | Real lessons blamed the private copy for a defeat and repeated harness advice. | — |
| 2026-10-23 | **A bare `--check` attaches to the condition in the same position**; `c1=cmd` still names one, and `FOO=1 npm test` works as a bare command. | A check without an id was silently ignored. | — |
| 2026-10-23 | **Pincer:** the first two heroes each work in their own copy at the same time. The approach that passes more checks wins outright (the Law). On a tie, judges from other companies compare both, authors hidden, in both orders; a judge whose answer flips with the order cancels itself out (the Trial). A split keeps both for you to choose at the Vault. The approach not chosen costs its hero no trust. Supports sit a Pincer out. | Running code beats judging code; order-swapped comparison removes position bias; trying hard things twice shouldn't punish the hero who lost. | — |
| 2026-10-23 | **The Seer is a hero you seat** (`savepoint seer <hero>`, or Settings): asked the same typed question three times with the options in a different order each time; only a unanimous answer clears the bar. Without a Seer, the Clerk's own reading counts as a weak guess. Outside decision services (Jev and others) will plug into this same seat. | Agreement across samples is the cheapest reliable confidence signal; rotating options removes position bias. | — |
| 2026-10-23 | **Debrief lessons:** after each battle a hero who didn't fight writes up to three one-line lessons into the lore, marked "lesson from <quest>, written by <hero>", never duplicated. Your reason for an undo is written as a **house rule**. Both are plain text in `chronicle/lore.md`, so you can edit or delete them. | The guild adapts to your project and to you; everything it learns stays visible and editable. | — |
| 2026-10-23 | **The Ledger learns from the leads you pick**: each time you choose someone other than the Council's suggestion, your pick gains half a win and the passed-over hero a quarter of a loss for that quest type, capped at 3 each. | Your preferences shape the suggestions, but real results always outweigh them. | — |
| 2026-10-23 | **Wait mode: a hero that tries something above its rank is paused and asks you** (allow once, deny, or hand the job to a hero who is allowed). Asking is never a failure; allowing once is logged and doesn't change trust; no answer within 5 minutes (`askTimeoutSec`) means no. Forbidden actions are still never asked about and still count as critical failures. | The harness should ask at real decision points rather than punish a hero for reaching its limit; your answer is how trust grows safely. | "Any attempt above your tier is a critical failure" |
| 2026-10-23 | **Questions live as small files in `chronicle/asks/`**, written atomically. The hook process waits on its file; the browser and `savepoint allow / deny / handoff` answer it. Answering never touches the world file, so it works mid-battle. | Works across processes and CLIs with no server needed. | — |
| 2026-10-23 | **A handed-off job joins the same battle:** the chosen hero takes the next turn and shares the outcome. | Hand-offs keep the quest moving instead of failing it. | — |
